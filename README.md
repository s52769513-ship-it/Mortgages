# מערכת ניהול משכנתאות

מערכת ניהול לסוכנות משכנתאות: לקוחות ולידים, תיקי משכנתא, משימות, מסמכים
ובקשות לבנקים — עם צ׳אט פנימי ויומן פעילות על כל ישות.

## מבנה

```
server/   Node + Express + TypeScript + Prisma (PostgreSQL)
client/   React + TypeScript + Vite + Tailwind (עברית, RTL)
```

## הרצה מקומית

נדרש Node 20+ ומסד PostgreSQL.

```bash
npm install

cp server/.env.example server/.env      # ואז לעדכן את DATABASE_URL ו-JWT_SECRET
npm run db:push --workspace=server      # יצירת הסכימה
npm run db:seed --workspace=server      # נתוני התחלה

npm run dev                             # API על 4000, ממשק על 5173
```

משתמש ראשוני מהזריעה: `admin@mortgages.local` / `Admin12345`.

## העלאה ל-Railway

שירות אחד מגיש גם את ה-API וגם את הממשק, כך שיש כתובת אחת ובלי CORS.

1. בפרויקט ב-Railway: **New → GitHub Repo**, ולבחור את הריפו ואת הברנץ'.
2. ב-**Variables** של השירות להוסיף:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}` (הפניה לשירות ה-Postgres)
   - `JWT_SECRET` = מחרוזת אקראית ארוכה
   - `NODE_ENV` = `production`
3. `railway.json` כבר מגדיר את הבנייה וההרצה. בכל דיפלוי רצה
   `prisma migrate deploy`, כך שהסכימה מתעדכנת לבד.
4. ב-**Settings → Networking** ללחוץ **Generate Domain** כדי לקבל כתובת.

   **חשוב — אחסון קבצים:** להוסיף לשירות **Volume** (למשל ב-`/data`) ולהגדיר
   `UPLOAD_DIR=/data/uploads`. בלי זה, מסמכים והקלטות נמחקים בכל דיפלוי, כי
   מערכת הקבצים של הקונטיינר לא שורדת הפעלה מחדש.
5. ליצירת המשתמש הראשון, להוסיף גם `ADMIN_EMAIL` ו-`ADMIN_PASSWORD`. בעלייה
   הראשונה שבה טבלת העובדים ריקה ייווצר מהם מנהל מערכת; אחרי שנכנסים ומחליפים
   סיסמה אפשר למחוק את שני המשתנים. כל עוד קיים ולו עובד אחד, המנגנון לא עושה
   כלום — הוא לא ידרוס חשבון קיים ולא יחזיר חשבון שנמחק.

## רשימת הבנקים והסניפים

הבנקים והסניפים נטענים מהמאגר הפתוח של data.gov.il, כך שהבחירה בטופס נשענת על
הרשימה הרשמית ולא על רשימה שהוקלדה ידנית.

להרצה — אחת מהשתיים:

```bash
npm run import:banks                  # משורת הפקודה
POST /api/banks/import                # מתוך המערכת, למנהל מערכת בלבד
```

הפעולה בטוחה לחזרה: רשומות קיימות מתעדכנות ושום דבר שהוזן ידנית לא נמחק. שמות
העמודות במאגר השתנו בעבר, ולכן הקוד מזהה כמה כתיבים אפשריים לכל שדה במקום
להסתמך על אחד.

**בנקאים לא מגיעים משום מאגר** — הם אנשי קשר אישיים. שם שמוקלד בטופס נשמר
ומופיע בבחירה בפעם הבאה, וכך ספר הקשרים של המשרד נבנה מעצמו.

## מודל הנתונים

12 ישויות: `Employee`, `Client`, `MortgageFile`, `Task`, `Document`, `Bank`
(עם `BankBranch` ו-`Banker`), `BankApplication`, `ExternalProfessional`,
`Communication`, `OfficeExpense`, `Reminder`, ובנוסף שתי טבלאות רוחביות:

- **`Comment`** — הצ׳אט הפנימי. פונה לכל ישות דרך `entityType` + `entityId`,
  ולכן אותו רכיב משמש בכרטיס לקוח, בתיק, במשימה, במסמך ובבקשה לבנק.
- **`ActivityLog`** — יומן פעילות שנרשם אוטומטית, כולל מי ביצע, מתי, ומה היה
  הערך לפני ואחרי.

### שלבי התיק

התיק נע בשישה שלבים, והם מה שהסטפר מציג:
`היכרות → איסוף מסמכים → בקשה לבנק → אישור עקרוני → בטחונות → ביצוע ותשלום`.

לחיצה על שלב **מסננת** את המשימות והמסמכים לאותו שלב — פעולה זולה והפיכה.
**העברת התיק** לשלב אחר היא שינוי אמיתי שנרשם ביומן, ולכן היא דורשת לחיצה
מפורשת נוספת על "העבר את התיק לשלב זה" שמופיעה מתחת לסטפר. כך אי אפשר להזיז
תיק בטעות בלחיצה אחת.

### סטטוסים

הנתונים שומרים את מלוא הפירוט — עשרה סטטוסי משימה, תשעה סטטוסי מסמך — אבל
התצוגה מקבצת אותם לארבעה מצבים בלבד: **הושלם / בטיפול / ממתין / דחוף**. המיפוי
נמצא ב-`client/src/lib/labels.ts`, והוא המקום היחיד שבו נקבעות התוויות בעברית.

## שכבת העיצוב

הטוקנים ב-`client/src/styles/index.css` ו-`client/tailwind.config.js` מתורגמים
ממפרט הנראות: פלטת פלדה על רקע `#f2f2f3`, ארבעה צבעי מצב, סקאלת רדיוסים
(6 / 10 / 16 / 20), שלוש מהירויות תנועה (120 / 180 / 220ms) ועקומה אחת.

כללים שנשמרים לאורך הממשק:

- צבע לעולם לא לבד — לכל תג יש מילה, ולכל שורת טבלה קו סטטוס בקצה.
- כפתור ראשי אחד למסך.
- לכל שדה תווית קבועה, ושגיאה מוצגת כטקסט מתחתיו ולא רק כמסגרת אדומה.
- מיקוד מקלדת גלוי בכל אלמנט, ו-`prefers-reduced-motion` מכבה תנועה.
- מספרים, סכומים ותאריכים בכיוון לטיני כדי שלא יתהפכו ב-RTL.

## מה קיים ומה עוד לא

**קיים:** כל תשע הישויות מהאפיון, כל אחת עם ממשק — לקוחות ותיקים, משימות,
מסמכים עם קבצים, בקשות לבנק מול הרשימה הרשמית, תקשורת, אנשי מקצוע חיצוניים,
הוצאות משרד, צ׳אט פנימי ויומן פעילות. בנוסף: חיפוש גלובלי, מיון ועימוד
ברשימות, התראות עם צליל, וניהול משתמשים.

**בהמשך (שלב 2 באפיון):** תזכורות אוטומטיות, כללי הסלמה, שילוב מייל, וסיווג
מסמכים אוטומטי.

### מספור רשומות

לכל משימה, מסמך ובקשה לבנק יש מספר רץ **בתוך התיק**, כדי שאפשר יהיה לומר
"משימה 3 בתיק" כמו שאומרים מספר תיק. המספר מוקצה ביצירה; אם שני אנשים יוצרים
באותו רגע, הניסיון השני מקבל את המספר הבא.

### הדשבורד

ארבעה מדדים, גרף הצנרת, ומתחתיהם המשימות שלי להיום מול מה שתקוע.

**"משימות להיום" סופר רק משימות שהיעד שלהן היום**, וחריגות נספרות בנפרד — כדי
ששני המספרים לא יתארו את אותה משימה פעמיים. המדדים הם על פני כל המשרד; הרשימה
מתחתיהם מסוננת למשתמש המחובר, ולכן היא נקראת "המשימות שלי".

צבעי הגרף אינם צבעי הממשק: הפלטה של המערכת מכוונת להיות עמומה, ומקטע צבע גדול
בגוונים האלה נקרא כאפור. הגרף משתמש בגוונים הקרובים באותה משפחה שעוברים את
בדיקת הרוויה ואת ההפרדה לעיוורי צבעים.

### הצ׳אט הפנימי

הודעות שלך ושל האחרים יושבות בצדדים מנוגדים. השרשור מתרענן לבד כל חמש שניות,
כך שהודעה של עמית מגיעה בלי לרענן את הדף.

אפשר לצרף קובץ, להקליט הודעה קולית (דרך המיקרופון בדפדפן), ולבחור למי ההודעה
מיועדת — הנמען מקבל התראה, ולחיצה עליה פותחת את הכרטיס שבו נכתבה.

התראה חדשה מלווה בצליל קצר. הוא מסונתז בקוד ולא נטען כקובץ, מושמע רק כשמספר
ההתראות שלא נקראו **עולה**, וניתן להשתקה מתוך תפריט הפעמון (הבחירה נשמרת
בדפדפן).

### אבטחה — מה נאכף ואיפה

- **הפעלה נכשלת על תצורה חסרה.** בלי `DATABASE_URL` או `JWT_SECRET` השרת מסרב
  לעלות ואומר מה חסר, במקום לדווח "בריא" ולהיכשל בהתחברות הראשונה. סוד קצר
  מ-32 תווים (או ערך ברירת המחדל) בפרודקשן אינו מפיל את השירות אלא נרשם
  כאזהרה בולטת בלוג בכל עלייה — אתר מושבת בגלל משתנה שהודבק בשירות הלא נכון
  הוא הנזק הגדול יותר.
- **בדיקת הבריאות נוגעת במסד.** `/api/health` מחזיר 503 אם השאילתה נכשלת, כך
  שהפלטפורמה מפעילה מחדש שירות שהקשר שלו למסד מת.
- **קבצים שהועלו אינם מתרנדרים אלא אם הם מסוג בטוח.** הדפדפן מתבקש להציג
  inline רק תמונות, PDF ואודיו, ולפי הסיומת שנשמרה — לא לפי הסוג שהמעלה הצהיר.
  כל השאר יורד כהורדה. אחרת קובץ `.html` שהועלה היה מריץ סקריפט תחת הדומיין
  של המערכת, עם כל מה שמשתמש מחובר יכול להגיע אליו.
- **קישור לקובץ עובד מהדפדפן.** אותו טוקן נשלח גם בעוגיית `HttpOnly`, כי
  `<a>`, `<img>` ו-`<audio>` לא יכולים לשאת כותרת. העוגייה מתקבלת לקריאה
  בלבד; כל שינוי חייב את הכותרת, שטופס מאתר זר לא יכול לזייף.
- **"צפייה בלבד" נאכף בכל נתיב.** חשבון `VIEWER` מקבל 403 על כל שינוי, בלי
  תלות בשאלה אם הנתיב זכר לבדוק.
- **ניחוש סיסמאות מתייקר.** עשרה כישלונות לכתובת מאותו לקוח, ואז המתנה של
  רבע שעה. בזיכרון — מספיק למשרד אחד.
- **כותרות דפדפן:** `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`,
  ו-`Permissions-Policy` שמשאיר מיקרופון לדומיין הזה בלבד (ההקלטות בצ׳אט).

**מה עדיין לא קיים:** בדיקות אוטומטיות, ו-CSP. שניהם שווים להוסיף לפני שהמערכת
גדלה.

### כללים שהשרת אוכף

- סטטוס המתנה במשימה מחייב לציין את הגורם שממתינים לו, וסגירת משימה מנקה אותו
  וחותמת את מועד הסיום.
- בנק, סניף ובנקאי נקלטים כטקסט חופשי ונוצרים בשימוש הראשון, כך שספר הקשרים של
  המשרד נבנה מעצמו.
- החלפת מסמך פותחת גרסה חדשה ומחזירה אותו לבדיקה, במקום לדרוס את הקודמת.
- לכל תיק יכולה להיות בקשה אחת מסומנת כ"בנק הנבחר"; סימון אחת מבטל את הקודמת.
- אי אפשר להשבית או להוריד בדרגה את מנהל המערכת הפעיל האחרון.
- אזכור של עצמך לא יוצר התראה.
